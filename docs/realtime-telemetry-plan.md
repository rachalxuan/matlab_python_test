# 仿真过程每秒更新界面的改造计划

日期：2026-10-09。基于当前工作区代码静态阅读；没有启动仿真、运行性能测试或修改业务代码。当前未提交的代码改动也属于本次阅读基线。

## 1. 目标和实时性定义

第一目标：仿真正在执行时，按现实时间约每 1 秒发布最新可用的接收样本窗口，界面更新星座、频谱和可用指标，结束后提供完整结果。现阶段按这一含义规划，尚未确认是否还要求计算速度跟上物理信号时间。

必须区分三个时间：

- `wallElapsedSec`：本次任务实际运行了多久。
- `simTimeSec`：信号处理到了哪个仿真时刻，由累计样本数和采样率确定。
- `windowStartSec/windowEndSec`：某张图真正覆盖的信号时间范围，必要时附流水线延迟及时间对齐说明。

每秒更新界面，不要求每秒生成一秒物理信号。计算速度用 `realTimeFactor = 已处理信号时长 / 实际计算耗时` 衡量；只有该值持续至少为 1，且处理延迟及积压有界，才满足持续跟随物理时间的要求。

图表更新目标也不是硬实时保证：生产约 1 秒一次、浏览器查询约 0.5 秒一次，正常情况下接收最新快照会额外等待一次查询间隔及网络、渲染时间。若单个计算调用长时间不返回，就不能承诺其间持续产生新图。需要拆解这些长调用，而不是重复发送旧图。

## 3. 推荐架构

```text
React 发起一个仿真任务
  -> Flask 现有队列
  -> MATLAB 初始化本任务的发射机、信道和接收机状态
  -> 循环处理小块：生成 -> 信道 -> 同步/均衡 -> 解调/译码
       -> 更新有限长度的图形缓冲区和可确认的统计
       -> 现实时间到发布点时，写 receiver-live.json
  -> Python GET /task_live/<taskId>?afterSeq=<n>
  -> React 更新已有 ECharts 实例
  -> 结束时强制发布末次快照，并返回现有最终结果
```

第一版保留 HTTP 短轮询，建议沿用 500 ms 查询、MATLAB 约 1000 ms 发布。新增独立轻量接口，避免在 `/task_status` 中反复带上 PNG、完整数组或全部时间线。

SSE 可以在有明确需求时替换浏览器这一段传输，但不会让 MATLAB 自动产生中间数据。当前部署默认 Waitress 单进程四线程，长连接设计还需要评估请求容量、断开连接和中间层缓冲。Flask 提供流式响应能力，但明确提示部分中间层可能影响流式行为，见 [Flask Streaming](https://flask.palletsprojects.com/en/stable/patterns/streaming/)。

运行中的轻量图形用数值数组，最终 PNG 留作保存、报告及现有历史结果。不要每秒调用完整绘图和 Base64 转换流程。

## 4. 分三类能力推进

### 4.1 阶段可视化：接通数据通道的过渡版本

在信道、同步等阶段完成时立即发布已经得到的真实图形，在可拆解的长循环中增加观测点。明确标注取样位置及更新时间。它能提前看到部分结果，但仍可能存在很长的空窗，不能作为“全流程每秒获得新同步星座”的最终验收。

### 4.2 连续图形：本次主要交付目标

将选定路径从发射到接收观察点改成状态连续的小块处理；每完成小块就更新图形缓冲区，到现实时间发布点再导出。频谱和同步星座能在整次任务结束前持续更新。

BER 初版可继续沿用结束后的审定算法。运行中的 EVM、锁定等只有在计算口径和证据可用时才显示，并与最终指标区分。最终选相位前的星座允许旋转，不能拿未来的最佳旋转修饰当前图形。

### 4.3 在线帧统计：后续独立里程碑

将帧同步、候选选择、FEC 输出、参考配对改成增量提交。只有这一阶段完成后，才能可靠地持续显示累计比较 bit、错误 bit、BER 和测量覆盖。

如果初版还需要保存完整输入/输出供最终评估，应明确它只支持有限长度任务；图形缓存有界不等于整个 MATLAB 进程内存已经有界。

## 5. MATLAB 分块设计

### 5.1 初始化一次，步进多次，结束收尾一次

建议新增可独立验证的入口和状态对象，例如：

```text
run_ccsds_tm_streaming_evaluation.m
HelperTMStreamingSession.m
  initialize(options)
  step(inputGroup)
  getLatestObservation()
  finalize()
HelperTMLiveMonitor.m
  observe(observation)
  publishIfDue()
  publishFinal()
```

这些名字是建议的新接口，不表示现有 helper 已能这样调用。原 `run_ccsds_tm_evaluation` 保留为批处理入口和结果回归基线；参数解析、物理定义及最终结果组装应抽成共享函数，避免复制整份大入口。

块边界按合法发射输入组、码字和必要的 DSP 粒度安排；同步之后输出长度可变，下游使用缓冲区衔接，不能假设固定输出点数。`comm.SymbolSynchronizer` 的输出就是可变长度，参见 [官方接口](https://www.mathworks.com/help/comm/ref/comm.symbolsynchronizer-system-object.html)。

先以现有定时模块的 50000 输入采样点作为某个环节的试验参考，不把它当作所有模式统一值。通过计时把主要步进调用控制在数十至数百毫秒量级；整帧 FEC 等不可进一步拆分的调用单独记录最坏耗时。若仍超过发布预算，就显示真实的数据陈旧状态，并继续优化瓶颈。

不要把 `blockSize = Fs` 当作每秒更新的实现。例如 30 Msym/s、8 sps 时，1 秒波形包含 2.4 亿个复采样点，仅一份 complex double 数组约 3.84 GB。

### 5.2 必须跨块保留的内容

| 模块 | 要保留的状态 / 改造点 |
|---|---|
| 数据源、组帧 | PN/随机数据源状态、帧计数、I/Q 路进度；预热只发生在任务开头 |
| 编码、映射 | 卷积编码器、打孔相位、随机化器、差分编码器、映射余数、码字缓冲 |
| 发射成形 | 同一个发射滤波对象及历史输入；不能每块插入新的起始瞬态 |
| CFO/时延 | 相位累加器、累计样本位置、分数时延滤波状态 |
| MAT 信道 | 已加载信道、全局时间、插值位置、多径延迟尾部；块首不回到 t=0 |
| 噪声 | 定义明确的参考功率、独立且可复现的随机序列；监控不能消耗业务 RNG |
| AGC | 增益、功率估计、启动状态；现有 HelperTMAGC 可传入/传出 state |
| 匹配滤波/定时 | FIR 历史、抽取相位、同一个 SymbolSynchronizer 及残留数据 |
| 载波/均衡 | 捕获窗口、频率/相位、环路积分器、抽头、训练/跟踪切换与可靠性状态 |
| 帧同步/FEC | ASM 跨块残片、锁定/失锁计数、Viterbi traceback、未满码字、I/Q 配对 |
| 观测与统计 | 环形缓冲区、样本序号、计数器、已提交帧编号、证据时间 |

### 5.3 已有 helper 的真实复用边界

- `HelperTMAGC.m` 有显式 state 接口，是较好的复用基础，但启动功率的取样范围仍需固定，避免依赖块大小。
- `HelperTMSymbolSynchronizerChunked.m` 在一次函数调用内部保留同一个对象，但每次调用都会重新创建对象，最后还会补零和裁剪。不能把它反复调用当作跨任务块的流式定时器；需要把对象生命周期和末尾处理拆出来。
- `HelperTMContinuousConvReceiver.m` 的 append 保留 Viterbi/打孔状态，但持续累积候选 bit，在 finalize 才搜索 ASM、选择候选和输出载荷。主入口目前也是整段 append 一次后立刻 finalize。在线 BER 需要新增安全的增量排帧接口，并限制候选缓存。
- `HelperTMAPSKPilotlessFrontEnd`、`HelperTMFeedforwardBlindPhaseSearch` 返回 state 不代表已经支持 state-in。需要明确历史窗口、相位连续展开、捕获/跟踪转换、窗口右侧未来样本及输出延迟。
- `HelperTMCompleteBurst` 的 guard continuation 用于结束时释放缓冲。正常块之间不能重复加 guard、重复预热或重置编码器。收尾 guard 只执行一次，且不纳入测量帧。

### 5.4 必须提前决定的数值语义

当前 `addReceiverNoise` 在 SNR 模式使用 `awgn(...,'measured')`，H 归一化也使用整段功率；直接按块重新估计会改变信道/噪声模型。PSD 模式同样有数值幅度与物理功率的标定。

因此分块前要确定：使用已知发射标定功率、明确长度的启动校准窗口，还是有限记录的预计算基准。无限持续流不能依赖未来整段均值。不同选项若改变物理定义，必须明确版本和验证口径，不能声称只是 UI 更新。

信道查询时间改为 `(globalSampleOffset + localSampleIndex) / Fs`；保留延迟能量跨块进入后续输出，连续信道文件按既有时间元数据衔接。

仅增加观测通道时要求结果完全一致。引入因果捕获、有限窗口估计后，不承诺与原离线全段估计逐样本完全相同；改用预先约定的捕获率、误码统计、覆盖率及误差容限验收。

## 6. 实时快照协议

建议新增 `receiver-live.json`，保持旧 `receiver-monitor.json` 的最终审定记录兼容。快照示意：

```json
{
  "schemaVersion": 2,
  "snapshotSeq": 21,
  "dataSeq": 18,
  "processingMode": "streaming-preview",
  "stage": "tracking",
  "wallElapsedSec": 21.3,
  "simTimeSec": 0.014,
  "publishedAtUnix": 1791500000,
  "constellation": {
    "seq": 18,
    "source": "post-carrier",
    "phaseStatus": "unresolved",
    "windowStartSec": 0.013,
    "windowEndSec": 0.014,
    "i": [0.62, -0.71],
    "q": [0.73, 0.68]
  },
  "spectrum": {
    "seq": 20,
    "source": "post-channel-pre-agc",
    "windowStartSec": 0.0139,
    "windowEndSec": 0.014,
    "frequencyMHz": [-1, 0, 1],
    "relativeDB": [-32, 0, -31]
  },
  "metrics": {
    "status": "not-ready",
    "comparedBits": null,
    "errorBits": null,
    "ber": null
  },
  "final": false
}
```

此处数组、序号和时间仅说明字段，不是实测数据。`taskId` 可由 Python 根据任务上下文附加，MATLAB 无需从输出目录猜测。

规则：

1. `snapshotSeq` 表示发布的新版本；`dataSeq` 只有真实信号处理推进才增加。各观察点可有独立序号和时间，避免把不同时刻的频谱、同步星座解释为同时采集。
2. 第一批有效样本立即发布，之后由 MATLAB `tic/toc` 按现实时间节流，结束强制发布。不要 `pause(1)`，也不要每块都算完整 FFT/JSON。
3. 星座从最新有限窗口抽取 1024–2048 点；从窗口内确定性选样，避免业务 RNG 被可视化改变。
4. 频谱从最新连续 2048/4096 个采样点加窗计算，再形成有限频点输出；绝不能先随意抽稀 IQ 再 FFT。
5. 固定取样位置、采样率、窗函数和单位。归一到峰值时标明“相对 dB”，需要看绝对功率变化时单独提供已标定功率；原实时相对频谱和最终物理 PSD 不能混用标签。
6. 状态/心跳可以更新而图不更新；页面显示图形最后的真实数据时间，不能把心跳当作新采样。
7. 无数据保留 null 和原因；BER 未可用时不是 0。空窗、失锁和任务结束有不同状态。

写入采用同目录临时文件、关闭后替换。沿用现有读取缓存的思路，并针对 Windows 文件占用、替换失败、半写入和旧缓存做测试；序号只能指向成功发布的完整文件。不要假定任意环境下 `movefile` 都能提供无需验证的事务保证。

Python 侧为 v2 新建解析/缓存或显式支持版本；现有 `MonitorSnapshots` 只接受 schemaVersion=1，不能直接拿它读取上述文件。

## 7. Python 和前端

### Python

- 新增 GET `/task_live/<taskId>?afterSeq=n`；未知任务、无快照、运行、停止和失败有明确返回。
- 未变更时仅返回任务状态和 `changed:false`，避免重复携带图形数组；响应设置 no-store。
- 读取任务目录中的快照，不向正在忙碌的同一个 MATLAB Engine 发起获取中间数组的请求。
- 短轮询采用最新值覆盖策略；慢客户端跳到最新图形，不排队回放过期 IQ。
- 在线帧记录使用另一条独立游标和有界分页。确认帧不能随图形丢弃，必要时追加写入日志；不要把全部历史每秒重写到 live 文件。
- 主任务的 completed/failed/cancelled 状态由现有任务系统负责，快照生成结束和 PNG 生成结束可以分别显示。
- 有限分块路径检查取消标记，实现协作式停止；现有 future.cancel 保留为兜底，前端等待后台确认后才显示“已停止”。

### 前端

- `src/apis/simulation.js` 新增实时接口封装。
- 新建 `useSimulationLive`，管理 taskId、序号、AbortController、单个在途请求、错误退避和末次读取。
- MatlabFFT 页面提交得到 taskId 就订阅实时数据，保留 finalResult 与 liveSnapshot 两种状态。不能再等 waitForSimulationTask 完成才呈现本任务图形。
- 抽出共享 `LiveSignalCharts`，MatlabFFT 与 ReceiverMonitor 使用同一数据协议和图形组件。
- ECharts 初始化一次，后续替换 series 数据；关闭更新动画、限制散点数量。当前 MatlabFFT 的 renderCharts 会 dispose/init，不适合直接每秒重复调用。
- 界面提供运行阶段、现实耗时、已处理信号时长、最后样本年龄、采样位置；已有结果、当前预览和回放分清。
- 断线显示数据陈旧；切任务和卸载时取消请求，晚到的旧任务响应不能覆盖新任务。
- 图形不依赖完整逐帧记录才能显示；在线统计完成后再逐步解耦 ReceiverMonitor 的 ready 判定。
- 用户暂停图形查看不等于暂停计算。当前离线回放按钮继续明确表示回放。
- 完成、失败、取消前后处理末次读取竞态，完成后停止轮询；默认只在最终保存时写历史结果，避免每秒写 localStorage。

## 8. 在线 BER 的单独改造

当前 computeBER 在整段结果上处理旋转候选、解码和参考配对。默认不少路径通过 ASM 选相位，也存在特殊路径的 BER/参考辅助候选选择；不能把候选内部计数直接当作正式累计量。

在线版本需要：

1. 通过接收可观测的 ASM、帧结构及可用校验信息确认相位和帧边界。
2. 维护有限捕获缓存，明确捕获、锁定、失锁、重捕获的迁移规则；未确认数据不进入已提交计数。
3. FEC 每产生完整且可确认的帧，按稳定帧标识对齐参考并提交一次。
4. 累计 BER 始终使用 `累计错误 bit / 累计实际比较 bit`，不平均各窗口 BER。
5. 预热帧、结束 guard 不计；未恢复和无法比较的帧列为覆盖缺口。
6. 帧计数回绕、跨块、I/Q 同时刻观测均不能重复计数。
7. `comm` 对象的 isLocked 是配置锁定概念，不能拿来充当接收机“载波已锁定”证据；沿用/改造真实遥测检测器。
8. 累计量一旦提交不追溯换候选；需要离线重评估时以独立最终审定结果展示。

## 9. 实施顺序与各阶段验收

| 阶段 | 工作与产物 | 完成条件 |
|---|---|---|
| P0 基线与计时 | 固定参数/随机输入；记录构帧、TX、信道、同步、FEC、统计、绘图耗时；列出首次可观测样本时间 | 明确最长阻塞步骤，保留原结果、误码分母和覆盖率 |
| P1 实时传输和图形 | live writer、v2 API、React hook、共享图表；真实阶段观测接入 | 任务完成前能显示真实窗口；契约及异常可验证。阶段快照不冒充连续接收 |
| P2 单一路径连续图形 | QPSK / single / 无 H / 无噪声 / 无编码 / 无均衡，逐项加入 RRC、CFO、时延、AGC，再接 AWGN | 小块持续贯通；超过发布周期的任务有多个不同窗口；状态不在块首重置 |
| P3 信道与接收扩展 | H 全局时间/延迟尾部、自适应均衡、已有 BPSK/8PSK/QAM 代表路径 | 人工跳变或衰落能按信号时间反映到图形，无块周期假瞬态 |
| P4 在线帧/FEC 统计 | 增量帧同步、卷积 append/drain、其他 FEC 码字缓冲、计数提交和持久化 | 逐帧增量之和等于最终累计，边界帧和未恢复帧均可解释 |
| P5 专用调制与打包 | APSK 的窗口/载波/增益状态，OQPSK/UQPSK 的两路关系，MSK/GMSK/其他专用链按需求逐项适配；更新部署文件清单 | 每个开放配置都有对应回归；未支持组合明确提示或显式选择批处理 |

P4 可在 P2 后先于全部 P3/P5 路径展开，取决于用户更需要完整调制覆盖还是在线 BER。推荐先交付“QPSK 真实连续图形”，再推进实际常用配置，不在第一轮承诺全部调制×编码×信道组合。

工作量集中在 P2–P5 的状态化和数值验证。P0 计时完成前不承诺精确工期，也不承诺从点击提交起一秒内必有同步星座；排队、初始化、捕获窗口和算法延迟必须单独计量。

## 10. 验证清单

- 观测开关：固定输入，监控开关前后输出、BER、覆盖率完全一致；可扩展现有 `test_web_monitor.m`。
- 分块不变性：同一输入用多种合法分块方式执行，测试跨 FIR、打孔周期、ASM、码字、I/Q 边界；确定性模块按误差容限比对。
- 随机一致性：噪声预生成或使用定义稳定的随机序列映射；仅固定 seed 而改变不同用途的随机调用顺序不足以证明输入相同。
- 在线正确性：已确认帧不重复、不回退；预热和 guard 排除；失锁后参考配对不串帧。
- 图形真实性：长任务在 completed 前出现递增 dataSeq 及移动窗口；只改变心跳序号不能通过。
- 通信健壮性：文件暂不可读、格式异常、旧序号、任务切换、慢网络、取消、失败和末次发布均测试。
- 单位和时间：图形采样位置、Fs、PSD/相对 dB、窗口时间及流水线延迟可核查；不能把 1 秒墙钟当作 1 秒仿真时长。
- 性能：记录首次真实图形延迟、有效更新间隔 P50/P95、最长空窗、快照体积、序列化时间、前端绘制耗时和监控额外开销。
- 建议验收预算：稳定运行期新图间隔以约 1 秒为目标，普通本机链路 P95 争取不超过 1.5 秒，监控额外耗时争取低于 5%；这些是待 P0/P2 验证的工程目标，不是现有实测保证。
- 长时间资源：图形数组和浏览器缓存有上限；如果要无限运行，还需候选 bit、参考帧、遥测历史和日志策略均有界，不能只限制散点数量。
- 回归：沿用 Python 监控测试、ReceiverMonitor/model 测试、参数契约测试及生产构建；分块 DSP 增加有针对性的 MATLAB 回归。新增后端文件纳入 deploy 打包及验收清单。

## 11. 第一版建议交付范围

一个任务运行期间，QPSK 基础链真正持续处理；星座和频谱约每秒更新；显示样本时间和数据年龄；支持查询、断线恢复、取消及最终结果。最终 BER 仍可使用现有审定流程，页面明确区分运行观测和最终统计。

完成这个闭环后，优先迁移用户常用调制/编码/信道。只增加 setInterval、循环调用完整 runOneShot、重复显示旧 PNG、重放最终数据，均不构成本目标的完成。

## 12. 跨块连续性的强制契约与实施门槛（根据后续讨论补充）

结论：上述架构以状态连续为目标，但规划本身不能证明实现正确。当前 helper 也尚未整体满足续接条件。跨块连续性应先通过自动化验证，再把相应配置开放为实时模式；不能用“图已经动起来”代替该验收。

实施顺序修订：先完成状态清单和最小路径的分块一致性测试，再接每秒展示；传输协议可独立准备。第 9 节的 P1 只属于通信能力验收，不意味着同步器已经能连续处理。

### 12.1 必须保存的内容超过“上一块最后相位”

每个处理模块建立状态契约，包含以下六类：

1. 算法递推状态：相位、频率、积分器、抽头、增益、功率估计。
2. 信号历史：FIR 延迟线、插值历史、跨窗口输入、未完成符号/ASM/码字。
3. 全局坐标：累计输入采样、输出符号位置、抽取余数、打孔相位、BPS 观察中心的全局步进。
4. 控制状态：捕获/跟踪/HOLD/重捕获模式、置信度历史、连续好坏计数、训练转判决导向的进度。
5. 待定输出：尚缺右侧窗口的尾部、待插值的相位区间、尚未确认的帧和不可提交的统计。
6. 固定配置及校准：本任务的参数、初始化窗口规则、功率基准；不能因一次 step 的长度而重新定义。

状态属于单个任务的 session。数值状态可显式 state-in/state-out，同步器等 System object 则保持同一个对象实例。不能用跨任务共享的无隔离 persistent 状态。

### 12.2 当前代码中已确认的具体风险

| 模块 | 当前实现 | 续接要求 |
|---|---|---|
| SymbolSynchronizer 包装 | 每次函数创建对象；末块补零并按输入长度裁剪 | 对象放到 session；普通块不 flush；不能每块按理论输出数裁剪 |
| Feedforward BPS | `frequencyState=0`、重新取 firstReliable、重新建立 history；观察中心从 1 开始 | 保存完整递推/捕获历史及全局观察网格；分块边界不能新增估计中心 |
| BPS 窗口 | 居中 movmean、居中 HOLD 膨胀、相邻中心插值；存在整段功率参考 | 缓存历史和待定尾部；等待足够右侧信息再提交；全段统计另行明确在线定义 |
| ComplexGainTracker | 每次从当前输入开头重新估初始功率及增益 | 仅初始化一次；续接 Gain、PowerIIR、PowerReference、Mode、Fade 和好坏计数 |
| 2-sps CMA | 每次新建 LinearEqualizer，截掉不足符号组的输入，并按整段功率归一化 | 复用对象；残余采样进入下一块；归一化和更新周期具有固定连续语义 |

| 连续卷积接收器 | 保存候选 Viterbi 状态，最终才选择并输出 | 保留已有递推能力，另加帧确认与增量输出；普通块不 finalize |

### 12.3 窗口算法采用“延迟提交”，避免伪造块末边界

例如对 101 符号居中窗口，窗口运算本身需要右侧 50 个符号。普通块最后 50 个位置应先缓存，下一块到达后再完成该窗口，而不是每块使用 Endpoints=shrink 结束一次窗口。实际 BPS 还叠加功率窗口、观察中心和插值，所以总等待量要按完整依赖链计算，不能直接认定为 50。

重叠数据用于计算边界窗口，但同一逻辑样本不能重复推进自适应状态，也不能向下游重复输出。只有任务真正结束时才能应用一次约定好的尾部规则。

若某个算法依赖全段中位数、全段最佳候选或未来整个记录，仅保存状态及有限重叠仍无法复现原离线行为。应保留有限记录预计算模式，或明确改成有限窗口在线算法并单独验证。不能把算法语义的变化隐藏在“分块优化”中。

### 12.4 连续性不变量

在同一初始化、同一输入及同一算法定义下：

```text
处理 A 后续接 B
与
处理拼接后的 A+B

应产生相同的有效输出序列和等价的最终递推状态。
```

比较时对齐全局采样/符号位置和固定流水线延迟，统一执行一次最终收尾。待定窗口与 pending 数据也是状态的一部分，不能通过忽略每块首尾误差让测试通过。

此不变量用于证明分块边界不改变一个已定义的处理算法。对依赖未来整段统计的旧算法，应另外做离线与在线算法性能回归，不能据此虚称完全等价。

### 12.5 必过测试

- 模块级：同一冻结输入用单段、等长块、不等长块及不同尾块划分；验证有效输出、最终递推状态、pending 数量和样本编号。低层接口不支持任意长度时由上层适配器缓存，不能丢弃。
- 边界级：把边界放在 RRC 记忆、定时插值、抽取周期、BPS 观察中心、相位跨 ±π、打孔周期、ASM 中间、码字中间和 I/Q 错位处。
- 状态切换级：在深衰落、HOLD、重捕获和训练切换附近分块；检查锁定轨迹和计数，防止一块结束就清零。
- 数据守恒：不丢失、不重复输出；允许下游因速率转换改变数量，但每一输出应有明确全局位置及来源。
- 刷新无关性：相同输入分别关闭监控以及使用不同发布周期，DSP 输出和指标一致。发布周期只能影响观察，不得决定 reset、训练长度或候选选择。
- 随机隔离：分块测试使用完全相同的已生成 IQ/噪声，避免随机调用顺序变化掩盖真正问题。
- 故障敏感性：至少验证一处人为 reset 或丢失残余采样会让相应测试失败，确保测试确实能发现状态断裂。

未通过连续性验证的模式保持批处理或明确显示为阶段预览。不能在实时模式中静默丢块、重置状态或依靠每块独立预热掩盖不连续。
