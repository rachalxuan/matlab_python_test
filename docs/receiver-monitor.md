# 接收监控

启动 Python 后台和前端后，从“信号调制”运行仿真，点击“打开接收监控”，或进入左侧“接收监控”。新页面自动关联最近提交的任务，也支持输入任务 ID。旧后台进程需要重启才能加载新增 HTTP 接口。

## 目前的实时性边界

当前接收机仍是整段处理，不是持续分块接收。MATLAB 在构造数据、信道处理、同步、译码等阶段写入真实阶段快照；页面每 500 ms 查询独立的轻量接口，不等待 MATLAB 引擎空闲。后台选定相位假设并完成参考配对后，才发布审定的逐帧记录和计数。不会把候选旋转的错误数混进最终累计值，也不会人为延迟逐条发送来伪装实时接收。

播放、暂停和时间滑块是明确标注的离线记录回放。它们不暂停 MATLAB、不改接收状态，也不改变 BER。真正持续接收需要另一项工作：跨块保留滤波器、载波环、定时环、均衡器、帧同步及 FEC 缓冲状态，并消除整段搜索及非因果参考配对的依赖。不能简单循环调用现有整段函数来替代。

## 状态与计数

载波、码元、帧同步灯使用 ReceiverTimeline 的实际观测。绿灯不代表比特正确，短时 cycle slip 可能仍通过星座质量检测。无观测或证据过期显示灰色，不把 null 当作 0。均衡器仅显示是否执行，不把内部 acceptance 当作锁定。没有独立译码锁定遥测的路径不伪造译码绿灯。

总比较 bit 只累加正式测量区已恢复且可与参考比较的数据；错误帧正常参与统计。预热不计入。没有比较量时 BER 为 N/A，未恢复帧单独列出，不填零误码或人为按一半比特错误计数。I/Q 同时刻观测成组显示，累计量取组末行，避免两路重复累计。每一路仍可在逐帧表和导出 JSON 中检查。时间线与接收环路观测之间含流水线延迟，属于近似对齐，不能单凭叠图证明因果关系。

测量覆盖不足时单独显示警告，并区分“未恢复”与“已恢复但未比较”。即使已比较部分 BER=0，也不能将测量不完整的任务判为通过。上游已经对齐的未编码、RS、LDPC、Turbo、TPC 原始 ASM 在固定帧槽进行旁路相关观测；该观测不重新搜索、不改变相位、不丢弃译码数据。卷积编码的 ASM 与 GMSK 的符号约定仍由原有专用路径处理，没有可用观测时保持灰色。

星座使用选定整体旋转后的 ctx.fineSynced 实际样本，全段均匀抽取最多 2048 点；频谱使用接收波形首 4096 点，归一到谱峰，相对 dB 而非绝对 dBm/Hz。两者均为静态快照，不随回放伪造时变 IQ。MSK/GMSK 不转换为假 QPSK 判决点。OQPSK 的半符号错位、UQPSK 的两路参数以及 CPM 的记忆不能由四点图独立判定。

前端模型测试 4 项、Python 接口测试 5 项通过；生产构建通过，仍有原有页面的未使用变量等警告。浏览器检查了时间滑块、播放、错误帧筛选、完整覆盖计数和覆盖不足警告；页面无浏览器错误日志。
